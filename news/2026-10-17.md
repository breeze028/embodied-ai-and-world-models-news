### 1. 【开源项目】Spark-0 独立仓库可读：从论文机制走向数据、训练与服务接口

**来源：** [作者项目页](https://xsparkai.com/Spark-0/) / [官方代码](https://github.com/XsparkAI/Spark-0)（T1）  
**类型：** Open Source（旧论文配套代码更新）  
**发布时间：** 仓库创建于北京时间 2026-10-17 01:26:19；本次检查固定到当日 15:27:43 的提交  
**评分：** 78.45/100  
**关键词：** 视觉触觉动作模型 · 数据接口 · 实时动作分块

**一句话：** 独立仓库在本窗口创建，现已包含模型接口、重定向与数据转换、训练配置、服务端和客户端；本次增量是可检查的实现及权重资源，不重复宣称论文首次发布。

**技术要点：**

- 代码基于修改后的 StarVLA，策略封装把观测预处理、触觉打包、末端位姿转换和动作解码接起来；接触图与 DA3 几何教师用于训练，部署不加载这些监督目标。项目页和代码互相链接，官方说明另支持 XPolicyLab 集成。
- 数据读取 Spark 专用的 LeRobot v3 布局，官方通用转换器输出不能直接当作兼容数据。磁盘中的双臂姿态和手关节为 54 维，四元数转为模型的六维旋转后为 58 维；转换还要求头相机外参，接触图依赖 MANO 等外部资产。该差异是数据表示转换，不是论文与代码的动作数量冲突。
- 服务采用 WebSocket：先更新观测，再逐行取得动作，策略按动作块推理并缓存其余动作。输入与检查点的相机、归一化、状态历史和触觉约定必须一致；按回合重置缓存，多个客户端需避免复用相同环境索引。没有触觉的流采用学习到的缺失表示，不能等同于零压力。
- [公开权重仓库](https://huggingface.co/TianxingChen/Spark-0)本次可访问且未设访问门槛，列出 `steps_400000_pytorch_model.pt`、完整配置和数据统计。HF 仓库创建于北京时间 16 日 01:51:46，最后修改于 17 日 13:50:01；这只能证明当前文件可用及本日有更新，不能证明所有权重首次上传于 17 日。本次未下载模型、安装依赖或运行真机。

**为什么值得关注：** 工程师现在可以核查训练和部署共用的输入输出契约，而不仅依据论文图示猜测接入方式。更重要的是公开默认配置与论文实验不同：固定提交中的预训练计划为 50 万步，公开权重标记为 40 万步；默认 RTC 在 50 步动作块剩余 34 步时触发，即每执行 16 步重规划，上一期精读所述论文实验为每执行 24 步。复现应同时固定源码、检查点内保存配置和部署覆盖参数，不能把 README 默认值当作论文原实验已经复现。

代码本身采用 MIT，并保留 XPolicyLab 适配与 MANO 等来源的单独说明；HF API 未提供独立权重许可字段，不将代码许可直接推定为全部模型与数据许可。没有核实 1000 小时 HumanTouch 数据集本体已公开下载。

### 2. 【开源项目】BAS-VLA 发布有限范围代码与离线 OpenVLA 残差适配器

**来源：** [作者项目页](https://nebulis-lab.com/BAS-VLA/) / [官方代码](https://github.com/NEBULIS-Lab/BAS-VLA) / [官方模型卡](https://huggingface.co/Shuaijun/BAS-VLA)（T1）  
**类型：** Open Source（九月论文的代码与适配器发布）  
**发布时间：** 两代码仓库均指向北京时间 2026-10-17 11:44:12 的 `Initial public release` 提交；模型仓库于本日 09:35:22 创建、11:45:26 更新  
**评分：** 72.25/100  
**关键词：** 冻结VLA · 任务语义变化 · 残差校准

**一句话：** 让冻结策略在外观变化但任务不变时保持行为，而在目标或约束改变时调整动作；公开实现将语义变化残差校准与选择性的外观保持辅助分开，并提供一个可审查的离线适配器。

**技术要点：**

- 训练记录对齐同一观测下的 clean / control / break 指令与动作。默认路径校准改变任务语义后的动作；保持分支用任务相关视觉探针和证据门控决定是否融合，避免对真正改变的任务盲目施加动作一致性。代码暴露 Frozen / Core / Pres / Full 模式，便于分别测试机制。
- [模型卡](https://huggingface.co/Shuaijun/BAS-VLA/blob/main/README.md)明确只覆盖 OpenVLA / LIBERO-10 的离线动作校准子集。资源清单含 400 条记录，按示范划分为训练 240、验证 80、测试 80，附 RGB、状态、场景、词表与归一化信息。适配器使用基础动作和二元词袋指令特征，公开元数据记录的目标配置为 `legacy`，不能默认为论文三项损失配置的完整复现。
- 适配器约定为 `openvla_libero10_unnormalized_sign_gripper_offline`，依赖指定动作统计及夹爪变换；它不是给 OpenPI 或 OpenVLA-OFT 任意检查点即插即用的通用权重。公开 CPU 示例仅展示对离线记录施加校准；其他主干的闭环评估需要相容适配器，真机还需硬件后端与标定。
- [BAS-VLA](https://github.com/NEBULIS-Lab/BAS-VLA) 与 [Beyond-Appearance-Shifts](https://github.com/NEBULIS-Lab/Beyond-Appearance-Shifts) 当前是同一提交 `51f0dab`，合并为一个事件。后一仓库早在 3 月创建，仓库创建时间不能当作本日技术首发依据；本条使用当前发布提交和 HF 资源时间，不声称能够据此证明历史上从未有过公开版本。

**为什么值得关注：** 这套接口使“任务不变应稳定”和“任务变化应响应”成为可分开检验的条件。评估时应同时检查旧目标和新目标：不再完成旧目标不等于完成新目标，离线动作距离也不等于闭环任务成功。发布范围和动作约定写得较清楚，但本次没有运行模型或闭环评估，不沿用旧论文的宣传数字为新权重背书；离线文件中更早的训练时间也不作为本日新训练结果。

**资源：** [固定发布提交](https://github.com/NEBULIS-Lab/BAS-VLA/tree/51f0dab5b2edab6539f3bccda7a04b3cb1d52a6c) · [支持范围](https://github.com/NEBULIS-Lab/BAS-VLA/blob/51f0dab5b2edab6539f3bccda7a04b3cb1d52a6c/docs/reproduction.md) · [适配器说明](https://huggingface.co/Shuaijun/BAS-VLA) · 原论文 [arXiv:2609.23650v1](https://arxiv.org/abs/2609.23650)，首次提交北京时间 2026-09-20 21:54:45。代码与本适配器模型卡列 MIT，上游运行时和模型权重分别遵守其来源许可。
